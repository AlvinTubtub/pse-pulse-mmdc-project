- Transaction review found and corrected a duplicate-run race. The PostgreSQL transaction advisory lock serializes the lookup and durable claim; its lock is released when the initial `RUNNING` claim commits, and the runner does not rely on it during inference. The unique `ProductionSession.trade_date` row is the durable guard after release. Newly ingested daily prices and their `MarketDataImport`, generated forecasts, and successful `PipelineRun`/`ProductionSession` completion are staged in the final transaction. Final validation failure rolls back all newly staged prices/imports/forecasts, then records `FAILED`; a previously approved import remains intact. Ordinary caught failures transition the run and session to `FAILED`. A process or host crash after the claim commit can leave `RUNNING`; the scheduler does not clear it. Recovery requires an owner to stop and verify the EOD process is no longer active, inspect the linked rows, change both linked records to `FAILED` in one reviewed maintenance transaction, and then use the explicit exact-date retry with the still-approved source and manifest. ## HTTPS path and limitation

The Nginx configuration requires a certificate for the VM's public IP and exposes only TLS on the already-approved 443 path. Let’s Encrypt currently supports IP identifiers on its `shortlived` profile; the profile is valid for 160 hours, so renewal needs reliable monitoring. lego’s current v5 documentation supports `run`, TLS-ALPN-01, `--profile`, `--renew-days`, `--cert.name`, and `--path`; it also documents that the old `renew` command and `--days`/`--disable-cn` forms changed in v5 ([lego v5 documentation](https://go-acme.github.io/lego/index.print.html), [Let’s Encrypt profiles](https://letsencrypt.org/docs/profiles/)). The renewal service is gated and disabled by default. It stops Nginx to hand port 443 to the ACME client and restores service only after certificate validation.

No certificate was requested and the renewal process was not exercised against ACME staging. Before public service, select and pin the exact lego v5 release and binary SHA-256, verify its actual version output and certificate path/layout, and prove staging initial issuance, renewal, external trust-chain validation, and recovery behavior. The current template has placeholder version and SHA values. The script intentionally refuses to install staging output and refuses initial issuance; therefore the current renewal helper cannot establish the first certificate. It uses a root-owned, mode-0600 configuration, versioned certificate directories, and an atomic `current` symlink. Until a separately reviewed initial-issuance and renewal path passes, do not enable Nginx or expose an insecure API.
